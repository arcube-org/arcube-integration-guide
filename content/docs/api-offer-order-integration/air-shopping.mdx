`POST /airshopping`

AirShopping is the entry point of every journey. It returns the ancillary offers available for a
trip (or a product-specific search) and creates a **ShoppingSession** whose id you carry into
[OfferPrice](/docs/api-offer-order-integration/offer-price).

There are two request shapes:

- **General AirShopping** — driven by the flight itinerary (`CoreQuery.Segments`). Returns
  itinerary-derived ancillaries: eSIMs, lounges, carbon offset, fast-track, baggage protection.
- **Product search** — driven by `ProductSearchInputs`. Required for **airport transfer**,
  **car rental** and **airport parking**, whose availability depends on parameters not derivable
  from an itinerary (locations, timing, driver, geocoordinates).

## General AirShopping

### Request schema

The body is a single `AirShoppingRQ` object with five sections.

#### `Document`

| Field | Type | Description |
| --- | --- | --- |
| `Name` | string | Free-form request label (tracing/debugging). |
| `ReferenceVersion` | string | Arcube NDC-like schema version, e.g. `"1.0"`. |

#### `Party`

| Field | Type | Description |
| --- | --- | --- |
| `Sender.AgentUser.Name` | string | Logical name of the calling system. |
| `Sender.AgentUser.IATA_Number` | string | Airline/TMC IATA identifier. |
| `Sender.AgentUser.PseudoCity` | string | PCC / tenant routing identifier. |
| `Recipient.SystemID` | string | Target system, typically `ArcubeAggregationEngine`. |

#### `CoreQuery.Segments[]`

Each segment is one leg of the journey.

| Field | Type | Description |
| --- | --- | --- |
| `SegmentKey` | string | Unique segment identifier. |
| `Departure.AirportCode` | string | IATA origin (e.g. `ATH`). |
| `Departure.DateTime` | string | ISO-8601 (UTC recommended). |
| `Arrival.AirportCode` | string | IATA destination. |
| `Arrival.DateTime` | string | ISO-8601. |
| `MarketingCarrier.AirlineID` | string | Marketing carrier code. |
| `MarketingCarrier.FlightNumber` | string | Flight number. |
| `OperatingCarrier.AirlineID` | string | Operating carrier code. |
| `PassengerRefs[]` | string[] | Passenger ids travelling on this leg. |

#### `DataLists.PassengerList.Passenger[]`

| Field | Type | Description |
| --- | --- | --- |
| `PassengerID` | string | Unique id, referenced by `PassengerRefs`. |
| `PTC` | string | Passenger Type Code: `ADT`, `CHD`, `INF`. |
| `Individual.Title` | string | e.g. `Mr`, `Ms`. |
| `Individual.GivenName` / `Individual.Surname` | string | Identity. |
| `Email` | string | Optional. Contact address for this traveller. Supplying it here means **OfferPrice never asks for the passenger list again** — see [Products](/docs/api-offer-order-integration/products#where-the-traveller-list-comes-from). Also read from `ContactInformation.EmailAddress.EmailAddressValue`. |
| `Phone.CountryCode` / `Phone.Number` | string | Optional contact number, split into dialling code and number. |
| `Associations.InfantRef` / `Associations.AssociatedAdultRef` | string | Links infants ↔ adults. |
| `LoyaltyProgram.ProgramCode` / `LoyaltyProgram.TierCode` | string | Optional loyalty enrichment for eligibility/personalization. |

#### `Metadata`

| Field | Type | Description |
| --- | --- | --- |
| `PointOfSale` | string | Sales channel — `AIRLINE_WEBSITE`, `WHITE_LABEL`, ... |
| `Tenant` | string | Arcube tenant id (optional; resolved from token). |
| `SessionID` | string | Your client-side reference for the search. |

<Callout type="warn" title="PointOfSale must use underscores">
  `AIRLINE_WEBSITE`, not `AIRLINE-WEBSITE`. A hyphenated value is rejected by the pricing engine.
</Callout>

### Example request

```json title="POST /airshopping"
{
  "AirShoppingRQ": {
    "Document": { "Name": "Arcube NDC-like AirShopping", "ReferenceVersion": "1.0" },
    "Party": {
      "Sender": { "AgentUser": { "Name": "Arcube API Client", "IATA_Number": "00000000", "PseudoCity": "ARC123" } },
      "Recipient": { "SystemID": "ArcubeAggregationEngine" }
    },
    "CoreQuery": {
      "Segments": [
        {
          "SegmentKey": "SEG1",
          "Departure": { "AirportCode": "ATH", "DateTime": "2026-09-29T08:00:00Z" },
          "Arrival": { "AirportCode": "FRA", "DateTime": "2026-09-29T10:00:00Z" },
          "MarketingCarrier": { "AirlineID": "XY", "FlightNumber": "XY123" },
          "OperatingCarrier": { "AirlineID": "XY" },
          "PassengerRefs": ["PAX1"]
        }
      ]
    },
    "DataLists": {
      "PassengerList": {
        "Passenger": [
          { "PassengerID": "PAX1", "PTC": "ADT", "Individual": { "GivenName": "John", "Surname": "Doe" } }
        ]
      }
    },
    "Metadata": { "PointOfSale": "AIRLINE_WEBSITE", "Tenant": "6941cc3502a186f72ba55226", "SessionID": "NDC-001" }
  }
}
```

### Response schema

The response separates commercial data (`OtherOffers`) from descriptive data
(`DataLists.ServiceDefinitionList`).

#### `OtherOffers`

| Field | Type | Description |
| --- | --- | --- |
| `Owner` | string | Always `"Arcube"`. |
| `OtherOffers[]` | array | The offers. |
| `OtherOffers[].OtherOfferID` | string | Unique offer id (used when selecting in OfferPrice). |
| `OtherOffers[].OfferItems[]` | array | Purchasable items (usually one). |
| `OtherOffers[].OfferItems[].OfferItemID` | string | Item id. |
| `OtherOffers[].OfferItems[].ServiceDefinitionRef` | string | Reference into `ServiceDefinitionList`. The prefix identifies the category (see below). |
| `OtherOffers[].OfferItems[].PriceDetail.TotalAmount.SimpleCurrencyPrice` | object | `{ amount, decimal, currency }`. |
| `OtherOffers[].PriceDetail.TotalAmount` | object | Offer-level total. |

#### `DataLists.ServiceDefinitionList[]`

| Field | Type | Description |
| --- | --- | --- |
| `ServiceDefinitionID` | string | Referenced by `ServiceDefinitionRef`. |
| `Name` | string | Commercial name. |
| `Description` | string | Human-readable description. |
| `MediaLink` | string | Image/media URL. |
| `ServiceTypeCode` | string | Category — `ESIMS`, `LOUNGE_ACCESS`, `CARBON_OFFSET`, `FAST_TRACK`, `AIRPORT_TRANSFER`, `CAR_RENTAL`. |
| `OtherServiceInformation` | object | Category-specific public metadata. |

#### `Metadata`

| Field | Type | Description |
| --- | --- | --- |
| `CorrelationID` | string | Echo of `x-correlation-id` (generated if you didn't send one). **Reuse it.** |
| `ShoppingSessionID` | string | The session id for this search. Send it back per selected offer in OfferPrice. |

### Selecting an offer by category

`ServiceDefinitionRef` is prefixed by category, which is the reliable way to filter offers:

| Category | Ref prefix |
| --- | --- |
| eSIM | `SVC-SIM` |
| Lounge access | `SVC-LNG` |
| Carbon offset | `SVC-CO2` |
| Fast-track | `SVC-FT` |
| Baggage protection | `SVC-BAG` |
| Airport transfer | `SVC-TRF` |
| Car rental | `SVC-CAR` |
| Airport parking | `SVC-PARK` |

<Callout type="info" title="Prefer priced offers">
  Some entries can be zero-priced placeholders. When selecting programmatically, choose an offer
  whose `PriceDetail.TotalAmount.SimpleCurrencyPrice.amount > 0`.
</Callout>

## Airport Transfer AirShopping

Point-to-point transfer discovery. Uses `ProductSearchInputs` with `ProductType: "AIRPORT_TRANSFER"`.

<Callout type="warn" title="Run a general AirShopping first, on the same correlation id">
  Issue a **general AirShopping** first (any itinerary) using the **same** `x-correlation-id`, then
  the transfer product search. The general recommendation determines the transfer **provider(s)**
  available for this trip — they're resolved server-side, so **you don't send a `providers` field**.
  If the general recommendation didn't offer airport transfer, the search returns
  `400 Airport transfer not supported for this session at this time of the trip`.
</Callout>

### Input fields

| Field | Required | Description |
| --- | --- | --- |
| `mode` | Yes | `one_way` or `round_trip`. |
| `num_passengers` | Yes | Passenger count. |
| `start_address` / `end_address` | Yes | Human-readable pickup/drop-off. |
| `start_coordinates` / `end_coordinates` | Yes | `{ lat, lng }` for each endpoint. |
| `pickup_datetime` | Yes | ISO-8601 **with an explicit UTC offset**, e.g. `"2026-12-24T13:00:00+02:00"`. Use a **future** date. |
| `return_pickup_datetime` | Conditional | Same format. Required when `mode` is `round_trip`. |
| `currency` | Optional | Shopping currency. Defaults from `Metadata`. |
| `requested_currency` | Optional | Display/settlement currency (triggers conversion; requires white-label origin). |
| `fromCountryCode` / `toCountryCode` | Yes | Country context. |
| `campaign` / `branch` | Optional | Merchandising / experiment context. |

<Callout type="warn" title="Pickup times need an offset">
  `"2026-12-24 13:00"` and `"2026-12-24T13:00"` are rejected — a transfer pickup is a real instant
  and a naive time would be read in the wrong zone. Send the offset, or `Z`.
</Callout>

`airline_id`, `pointOfSale` and the transfer **providers** are **not** client inputs — the first
two are taken from `Metadata.Tenant` / `Metadata.PointOfSale`, and the providers are resolved from
the general recommendation on this session (see the callout above).

### Example request

```json title="POST /airshopping"
{
  "AirShoppingRQ": {
    "Document": { "Name": "Arcube NDC-like AirShopping", "ReferenceVersion": "1.0" },
    "Party": {
      "Sender": { "AgentUser": { "Name": "Arcube API Client", "IATA_Number": "00000000", "PseudoCity": "ARC123" } },
      "Recipient": { "SystemID": "ArcubeAggregationEngine" }
    },
    "ProductSearchInputs": [
      {
        "ProductType": "AIRPORT_TRANSFER",
        "Input": {
          "mode": "one_way",
          "num_passengers": 1,
          "start_address": "Athens International Airport (ATH), Spata, Greece",
          "end_address": "Cholargos, Greece",
          "pickup_datetime": "2026-07-23T15:00:00+03:00",
          "currency": "USD",
          "requested_currency": "DOP",
          "start_coordinates": { "lat": 37.936175, "lng": 23.9465255 },
          "end_coordinates": { "lat": 37.9975628, "lng": 23.8027203 },
          "fromCountryCode": "GR",
          "toCountryCode": "GR"
        }
      }
    ],
    "Metadata": { "PointOfSale": "WHITE_LABEL", "Tenant": "6941cc3502a186f72ba55226", "SessionID": "NDC-TRF" }
  }
}
```

### Response

Same normalized shape — one `OtherOffer` per transfer option, each referencing one `SVC-TRF-...`
service definition. `OtherServiceInformation` typically exposes `pickupAddress`, `dropoffAddress`,
`pickupTimeIso`, `vehicleType`, `providerName`, `maxPassengers`, `maxBags`, and `amenities`.

## Car Rental AirShopping

Dedicated rental search. Uses `ProductSearchInputs` with `ProductType: "CAR_RENTAL"`.

<Callout type="warn" title="Run a general AirShopping first, on the same correlation id">
  Issue a **general AirShopping** first (any itinerary) using the **same** `x-correlation-id`, then
  the car-rental product search. The general recommendation determines the car-rental
  **provider(s)** available for this trip — they're resolved server-side, so **you don't send a
  `providers` field**. If the general recommendation didn't offer car rental, the search returns
  `400 Car rental not supported for this session at this time of the trip`.
</Callout>

### Input fields

| Field | Required | Description |
| --- | --- | --- |
| `currency` | Optional | Shopping currency. Defaults from `Metadata`. |
| `requested_currency` | Optional | Display/settlement currency. |
| `fromCountryCode` / `toCountryCode` | Yes | Country context. |
| `driver.age` | Yes | Driver age (eligibility / rate filtering). |
| `driver.date_of_birth` | Yes | `YYYY-MM-DD`. |
| `driver.residence` | Yes | Driver residence country code. |
| `pickup_at` / `dropoff_at` | Yes | ISO-8601 **with an explicit UTC offset**, e.g. `"2026-12-25T10:00:00+00:00"`. Use **future** dates; `dropoff_at` must be after `pickup_at`. |
| `pickup_location` | Yes | `{ iata }` or `{ id }`. |
| `dropoff_location` | Optional | `{ iata }` or `{ id }`. Omit for pickup-location return. |

### Example request

```json title="POST /airshopping"
{
  "AirShoppingRQ": {
    "Document": { "Name": "Arcube NDC-like AirShopping", "ReferenceVersion": "1.0" },
    "Party": {
      "Sender": { "AgentUser": { "Name": "Arcube API Client", "IATA_Number": "00000000", "PseudoCity": "ARC123" } },
      "Recipient": { "SystemID": "ArcubeAggregationEngine" }
    },
    "ProductSearchInputs": [
      {
        "ProductType": "CAR_RENTAL",
        "Input": {
          "currency": "USD",
          "requested_currency": "DOP",
          "fromCountryCode": "MX",
          "toCountryCode": "MX",
          "driver": { "age": 37, "date_of_birth": "1989-07-06", "residence": "DO" },
          "pickup_at": "2026-07-15T12:15:00-05:00",
          "dropoff_at": "2026-07-24T18:00:00-05:00",
          "pickup_location": { "iata": "CUN" }
        }
      }
    ],
    "Metadata": { "PointOfSale": "WHITE_LABEL", "Tenant": "6941cc3502a186f72ba55226", "SessionID": "NDC-CAR" }
  }
}
```

### Response

One `OtherOffer` per rental option, each referencing a `SVC-CAR-...` service definition. The
public `OtherServiceInformation` includes vehicle and location detail (car name, category,
transmission, seats, pickup location, rental days, mileage, cancellation type and whether the rate
is instant-confirmation).

The identifiers required for booking are resolved automatically and carried into OfferPrice — **as
is the `driver` block**, so the driver's date of birth and residence are never asked for a second
time.

<Callout type="warn" title="Check `InstantConfirmation` before selling">
  A rate whose `OtherServiceInformation.InstantConfirmation` is `false` is **on request**: the
  supplier does not confirm at booking time and the order line can stay `PENDING` indefinitely. If
  you need a guaranteed car, filter on this flag.
</Callout>

## Airport Parking AirShopping

Geo-based parking search around an airport. Uses `ProductSearchInputs` with
`ProductType: "PARKING"`.

<Callout type="warn" title="Run a general AirShopping first, on the same correlation id">
  Issue a **general AirShopping** first using the **same** `x-correlation-id`, then the parking
  product search. The general recommendation establishes that parking is on sale for this trip; if
  it wasn't offered, the search returns
  `400 Parking not supported for this session at this time of the trip`.
</Callout>

### Input fields

| Field | Required | Description |
| --- | --- | --- |
| `lat` / `lng` | Conditional | Search centre. Provide these **or** `airportIata`. |
| `airportIata` | Conditional | 3-letter IATA code; Arcube resolves it to coordinates. |
| `fromDate` / `toDate` | Yes | Stay start/end as **lot-local wall clock**, `"YYYY-MM-DD HH:mm:ss"`. `toDate` must be after `fromDate`. |
| `numberOfSpots` | Optional | Spots to reserve. Defaults to `1`. |
| `page` / `pageSize` | Optional | Pagination. Default `1` / `10`; `pageSize` max `50`. |
| `currency` | Optional | Shopping currency. |
| `requested_currency` | Optional | Display/settlement currency. |

<Callout type="warn" title="Parking dates carry no timezone — deliberately">
  Unlike airport transfer and car rental, parking times are the **lot's own wall clock**: the gate
  opens at 21:20 by the lot's clock, wherever you are. An offset or a trailing `Z` is **rejected**
  rather than stripped, because silently discarding it would shift the booking. `"T"` is accepted
  as the separator and seconds may be omitted. Each returned product carries the lot's zone as
  `locationInfo.timezone`, so you can still resolve the instant.
</Callout>

### Example request

```json title="POST /airshopping"
{
  "AirShoppingRQ": {
    "Document": { "Name": "Arcube NDC-like AirShopping", "ReferenceVersion": "1.0" },
    "Party": {
      "Sender": { "AgentUser": { "Name": "Arcube API Client" } },
      "Recipient": { "SystemID": "ArcubeAggregationEngine" }
    },
    "ProductSearchInputs": [
      {
        "ProductType": "PARKING",
        "Input": {
          "lat": 39.051351,
          "lng": -84.6671453,
          "fromDate": "2026-08-28 21:20:00",
          "toDate": "2026-09-05 21:20:00",
          "numberOfSpots": 1,
          "page": 1,
          "pageSize": 10,
          "requested_currency": "USD"
        }
      }
    ],
    "Metadata": { "PointOfSale": "AIRLINE_WEBSITE", "Tenant": "6941cc3502a186f72ba55226", "SessionID": "NDC-PARK" }
  }
}
```

### Response

One `OtherOffer` per lot × parking type, each referencing a `SVC-PARK-...` service definition.
`OtherServiceInformation` exposes `Lot`, `ParkingType`, `Address`, `City`, `Latitude`, `Longitude`,
`Timezone`, `CheckIn`, `CheckOut`, `Spots`, `AmountDueAtLocation`, `QuoteTTLSeconds` and
`CancellationPolicies`.

<Callout type="info" title="Sold-out lots are not returned">
  The supplier reports lots that have no availability for your dates. They are **omitted** rather
  than published — an offer you cannot buy would only fail after the customer has paid — so the
  offer count can be lower than the supplier's `totalLots`.
</Callout>

<Callout type="warn" title="Quotes are short-lived">
  `QuoteTTLSeconds` is typically `300`. Cart the offer promptly; a stale quote is rejected at
  booking.
</Callout>

<Callout type="info" title="Empty results are a valid response">
  If a search returns zero offers, the criteria (dates, location, availability) yielded nothing —
  it is not an error. Verify dates are in the future and the coordinates are near an airport with
  partner lots.
</Callout>

Continue to [OfferPrice](/docs/api-offer-order-integration/offer-price) to cart and price your
selection.
