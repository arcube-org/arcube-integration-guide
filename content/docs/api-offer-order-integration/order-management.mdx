After an order is created you can retrieve it individually or list a customer's orders.

## OrderView

`POST /orderview` — retrieve a single order and its current status.

### Request

| Field | Required | Description |
| --- | --- | --- |
| `OrderViewRQ.OrderID` | Yes | The order identifier. Accepts either the **transaction id** returned by OrderCreate (`Order.OrderID` / `Order.TransactionRef`) or the order's **PNR / session id**. |
| `OrderViewRQ.tenant` | No | Tenant context. |

```json title="POST /orderview"
{
  "OrderViewRQ": { "OrderID": "1bf8e39a-5934-4f2e-a283-af1ff9c1e9db" }
}
```

<Callout type="info" title="Headers">
  Send `Authorization: Bearer <token>` and, optionally, `x-correlation-id` for traceability.
</Callout>

### Response

| Field | Description |
| --- | --- |
| `Order.OrderID` | The resolved order id. |
| `Order.Status` | Roll-up status across the order's items (e.g. `CONFIRMED`, `PARTIALLY_CONFIRMED`, `REFUNDED`, `FAILED`). |
| `Order.AssociatedRecords[]` | Linked records — the `PNR` and the underlying transaction id(s) (`TX`). |
| `Order.Customer` / `Order.Passengers[]` | Buyer and traveller details. |
| `Order.Items[]` | One entry per booked line: `OrderItemID`, `Name`, `ServiceTypeCode`, `Quantity`, `Status`, `PriceDetail.TotalAmount`, `Metadata`, plus the **delivered product** (see below). |
| `Order.PriceSummary` | `{ Currency, GrandTotal }` for the order. |
| `Order.CancellableItems[]` | One entry per line with its live `Status`, a `Cancellable` flag and the booking-time `CancellationPolicy`. Pass an `ItemID` to [OrderCancel](/docs/api-offer-order-integration/order-cancel). |
| `Metadata.CorrelationID` | Correlation id for traceability. |

All money is in **major units** — `{ "amount": 33.17, "currency": "USD" }` means $33.17. (The
mille-scaled `{ amount, decimal, currency }` form appears only in AirShopping offers.)

An unknown id returns `400 Order not found`.

```json
{

    "Document": { "Name": "Arcube NDC-like OrderView Response", "ReferenceVersion": "1.0" },
    "Order": {
      "OrderID": "1bf8e39a-5934-4f2e-a283-af1ff9c1e9db",
      "Status": "CONFIRMED",
      "Owner": "Arcube",
      "CreatedAt": "2026-07-15T10:53:48.927Z",

        { "Type": "PNR", "ID": "ARC000013" },
        { "Type": "TX", "ID": "1bf8e39a-5934-4f2e-a283-af1ff9c1e9db" }
      ],
      "Customer": { "Name": "Jane Doe", "Email": "jane.doe@example.com", "Phone": "+302100000000" },
      "Passengers": [ { "Name": "Jane Doe", "Email": "jane.doe@example.com" } ],
      "Items": [
        {
          "OrderItemID": "ORDI-1",
          "ServiceTypeCode": "LOUNGE_ACCESS",
          "Name": "Goldair Handling CIP Lounge",
          "Quantity": 2,

          "Passengers": [ "... see the per-product sections below ..." ],

          "PriceDetail": { "TotalAmount": { "amount": 33.17, "currency": "USD" } },
          "Status": "CONFIRMED"
        }
      ],
      "PriceSummary": { "Currency": "USD", "GrandTotal": 33.17 },

        {
```

<Callout type="info" title="ItemID is the OrderItemID">
  `CancellableItems[].ItemID` and `Items[].OrderItemID` are the **same** positional label
  (`ORDI-1`, `ORDI-2`, ...), and that is what you pass to OrderCancel. Supplier-side item
  identifiers are resolved for you and are not part of the response.
</Callout>

## What each product returns

Everything the customer needs in order to *use* what they bought is on `Items[]`, in a block named
after the category. The same blocks appear on the
[OrderCreate](/docs/api-offer-order-integration/order-create) response, so a retrieved order and a
freshly booked one carry the same detail.

| `ServiceTypeCode` | Where the deliverable lives | Level |
| --- | --- | --- |
| `ESIMS` | `Passengers[].ESIM` | per traveller |
| `LOUNGE_ACCESS` | `Passengers[].LoungePass` | per traveller |
| `FAST_TRACK` | `FastTrack` + `Passengers[].FastTrackVoucher` | item + per traveller |
| `CARBON_OFFSET` | `CarbonOffset` | item |
| `BAGGAGE_PROTECTION` | `BaggageProtection` (incl. `Policies[]`) | item, with a per-traveller array |
| `AIRPORT_TRANSFER` | `Transfer` | item |
| `CAR_RENTAL` | `CarRental` | item |
| `PARKING` | `Parking` | item |

<Callout type="info" title="A block appears only once the vendor has delivered">
  While a line is `PENDING` — an on-request car-rental rate, an asynchronous baggage policy — there
  is no confirmation to publish, so the block is absent and `Status` tells you why. Poll OrderView
  until `Status` is `CONFIRMED`. A `FAILED` or `REFUNDED` line likewise carries no block; read
  `StatusReason` and `Refund`.
</Callout>

<Callout type="warn" title="Partial delivery is visible, not implied">
  `Fulfillment` (`RequestedQuantity` / `DeliveredQuantity` / `FailedQuantity`, plus `FailedReason`)
  appears on every per-unit product. A line can be `CONFIRMED` overall while one unit failed — check
  the counts rather than assuming all `Quantity` were delivered.
</Callout>

| Field | Description |

| `FastTrack.EPass.Usages` | `{ available }` — entries remaining on the pass. |

### Baggage protection — `BAGGAGE_PROTECTION`

Item-level, with `Policies[]` as the per-traveller array — one agreement is issued per insured
person.

| Field | Description |
| --- | --- |
| `BaggageProtection.Product` | `{ Type, Code, Name, ReferenceLabel, TermsURL }`. `ReferenceLabel` is what the supplier calls the policy number, so support and the customer use the same words. |
| `BaggageProtection.Coverage.HeadlineCode` | Which benefit to lead with in the UI. |
| `BaggageProtection.Coverage.Benefits[]` | `{ Code, Label, Unit, Amount, Currency }`. `Unit` is `MONEY` (format with `Currency`) or `COUNT` (a bare number). |
| `BaggageProtection.Terms.PayoutTriggerHours` | The guarantee: bag not returned within this many hours and the passenger is paid. |
| `BaggageProtection.Terms.ReportDeadlineHours` | The window the passenger must report inside, or lose the guarantee. |
| `BaggageProtection.Claims.TrackingURL` / `.Email` | Where the passenger goes when a bag is missing. |
| `BaggageProtection.Flight` | The itinerary the cover is attached to — one per booking, not per policy. |
| `BaggageProtection.Policies[]` | `{ PolicyNumber, CustomerReference, Status, IssuedAt, Passenger }` — one per traveller. |

  `Fulfillment` gives you the counts.

<Callout type="info" title="No CancellationPolicy on this block">
  Baggage protection carries no product-level cancellation terms. Refundability for the line is
  reported on `Order.CancellableItems[]`.
</Callout>

### Airport transfer — `AIRPORT_TRANSFER`

Item-level: a transfer is one vehicle for the whole party.

| Field | Description |
| --- | --- |
| `Transfer.Booking.ReservationID` | The supplier reservation. |
| `Transfer.Booking.ConfirmationNumber` | What the passenger quotes to the driver or to support. |
| `Transfer.Booking.Supplier` | `{ Name, Phone, Email }` — the operator to call on the day. |
| `Transfer.CancellationPolicy` | `{ Text, Refundable, RefundPercentage, CutoffHours, Tiers[] }`. |
| `Transfer.Legs[]` | One per direction (`outbound`, `return`). |
| `Transfer.Legs[].PickupLocation` / `.DropoffLocation` / `.PickupTime` | Where and when. |
| `Transfer.Legs[].Flight` | The flight the leg is tracked against. |

### Car rental — `CAR_RENTAL`

Item-level: one vehicle for the booking.

| Field | Description |
| --- | --- |
| `CarRental.Booking` | `{ Reference, Status: { Code, Label }, IsOnRequest, ContactEmail }`. |
| `CarRental.Vehicle` | Name, category, transmission, seats, doors, image, `Specs`. |
| `CarRental.Supplier` | Desk operator name and contact. |
| `CarRental.Driver` | The named driver. |
| `CarRental.Itinerary` | `{ Pickup: { DateTime, Location }, Dropoff: { ... } }`. `Location.Instructions` is **how the driver finds the desk**. |
| `CarRental.Mileage` | `{ Unlimited, Limit }`. |
| `CarRental.Inclusions[]` / `CarRental.Protections[]` | What the rate already covers. |
| `CarRental.Notices[]` | The supplier's binding terms — **including the credit-card pre-authorisation**, without which the traveller is refused the car. |
| `CarRental.Extras[]` | **Mandatory charges payable at the desk** (airport surcharge, winter tyres). Not part of what Arcube collected. |
| `CarRental.CancellationPolicy` | Refund terms. |

### Airport parking — `PARKING`

Item-level: one reservation covers every spot.

| Field | Description |
| --- | --- |
| `Parking.Booking` | `{ ReservationID, Status, OrderDate }`. `ReservationID` is what a cancellation is issued against. |
| `Parking.Reservation` | `{ Number, CheckIn, CheckOut, Days, Spots, ParkingType, MinimumBookingDays, ExtraFields[] }`. |
| `Parking.Lot.Name` / `.Address` / `.City` / `.Phone` | Which lot, and how to reach it. |
| `Parking.Lot.Timezone` | The lot's zone. **`CheckIn` / `CheckOut` are lot-local wall clock**, so pair them with this to get an instant. |
| `Parking.Lot.Directions` | Map link. |
| `Parking.Lot.ShuttleInfo` / `.ShuttleDetails` | How the driver gets from the lot to the terminal. Supplier-authored HTML, carried verbatim. |
| `Parking.Lot.SpecialConditions` / `.Description` | Supplier-authored HTML. |
| `Parking.Lot.PrintedReceiptRequired` | Some lots refuse entry without a printed receipt. |
| `Parking.AmountDueAtLocation` | `{ Amount, Currency }` — **payable on arrival, in the lot's currency**, and not collected by Arcube. |
| `Parking.CancellationPolicy` | Refund terms as the vendor stated them at booking. |

```json
{

  "ServiceTypeCode": "PARKING",

    "Reservation": {
      "Number": "RAR833691",
      "CheckIn": "2026-08-28 21:20:00",
      "CheckOut": "2026-09-05 21:20:00",
      "Days": 8,
      "Spots": 1,
      "ParkingType": "Covered, Self",
```

## What is never returned

The order response carries what the customer needs to use their purchase. It does not carry:

- **Cost and margin data** — what Arcube or the airline paid or earned on the line.
- **Supplier and provider identities** — the underlying vendor behind an offer is not named.
- **Supplier-side identifiers** — search and quote references, rate and location keys, and any
  deep links into a supplier's own systems.

`Items[].Metadata` echoes the context you supplied at OfferPrice (passengers, the fast-track slot,
parking extra fields) with those keys stripped.


## OrderList

`POST /orderlist` — list all orders for a customer within a tenant.

### Request

| Field | Required | Description |
| --- | --- | --- |
| `OrderListRQ.tenant` | Yes | Tenant identifier. |
| `OrderListRQ.email` | Yes | Customer email to filter by. |

```json title="POST /orderlist"
{
  "OrderListRQ": { "tenant": "<your-tenant-id>", "email": "jane.doe@example.com" }
}
```

### Response

Returns one summary row per order (newest first) with a `Count`. Both `tenant` and `email` are
required; omitting either returns `400`. A customer with no orders returns an empty `Orders` list.

| Field | Description |
| --- | --- |
| `Orders[].OrderID` | The transaction id — pass it to OrderView. |
| `Orders[].Status` | Order status. |
| `Orders[].CreatedAt` | ISO-8601 creation timestamp. |
| `Orders[].Currency` / `Orders[].GrandTotal` | Order total (major units). |
| `Orders[].PNR` | The order's record locator. |
| `Orders[].ItemCount` | Number of items in the order. |
| `Count` | Number of orders returned. |
