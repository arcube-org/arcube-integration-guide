`POST /ordercreate`

OrderCreate books the cart referenced by a `PricedSessionID`. It checks out the cart, confirms the
order, and fulfils it with the underlying providers — returning an `OrderID` and an aggregation
`TransactionRef`.

<Callout type="warn" title="Two mandatory headers">
  - `x-correlation-id` — the **same** value used on AirShopping and OfferPrice.
  - `x-idempotency-key` — a fresh UUID per booking attempt; guarantees the order is created at
    most once.
</Callout>

<Callout type="info" title="Payment is proven, not collected">
  Arcube does not collect payment here — the seller has already captured it. Prove that with an
  **`externalPSP`** payment block (sent in `Payments[0]`): only `Provider` and `ReferenceId` are
  required; the rest is derived from the priced cart. See [Payments](#payments).
</Callout>

## Request schema

The body is a single `OrderCreateRQ`.

| Field | Required | Description |
| --- | --- | --- |
| `Document.Name` / `Document.ReferenceVersion` | Yes | Label + schema version. |
| `PointOfSale` | Yes | `{ SalesChannel, Seller, Owner, CountryCode }`. `SalesChannel` mirrors the shopping channel (`AIRLINE_WEBSITE` / `WHITE_LABEL`). |
| `Customer.PrimaryContact` | Yes | Buyer identity and contact (see below). |
| `Passengers[]` | Yes | Traveller records (`PassengerID`, `PTC`, `Individual`). |
| `Query.PricedOfferRef.OfferID` | Yes | A priced offer id from OfferPrice. |
| `Query.OfferItems[]` | Yes | Item references from OfferPrice. |
| `Payments[]` | Yes | The `externalPSP` proof-of-payment block (see below). |
| `Metadata.SessionID` | Yes | The **CorrelationID** used across the flow. |
| `Metadata.Tenant` | Yes | Tenant id. |
| `Metadata.PricedSessionID` | Yes | The cart id from OfferPrice. |
| `Metadata.PNR` | Conditional | Airline record locator. Optional **only if Arcube has enabled no-PNR ordering for your tenant** — then you omit it and the order generates its own. Otherwise a real PNR is required. Either way, a stale/unknown PNR is rejected with `404 Recommendation schedule not found`. |

<Callout type="info" title="OrderCreate books the whole cart">
  The transaction is bound to the `PricedSessionID`, which represents the entire cart. For a
  multi-item cart, `Query.PricedOfferRef`/`OfferItems` need only reference one valid priced offer;
  every item in the cart is booked, and the response lists them all with the combined total.
</Callout>

### `Customer.PrimaryContact`

| Field | Description |
| --- | --- |
| `Title` | e.g. `Mr`, `Ms`. |
| `GivenName` / `Surname` | Buyer name. |
| `Email` | Contact email (required). |
| `DateOfBirth` | `YYYY-MM-DD`. |
| `Phone.CountryCode` / `Phone.Number` | Contact phone. |
| `Address.Line1` / `City` / `PostalCode` / `CountryCode` | Billing address. |

### `Payments[]`

`Payments[0]` is the `externalPSP` proof that the seller already collected payment. Only the first
two fields are required — the rest default from the priced cart.

| Field | Required | Description |
| --- | --- | --- |
| `Provider` | Yes | The PSP / payment provider that captured the funds (e.g. `airline-psp`). |
| `ReferenceId` | Yes | The provider-side payment reference. |
| `Currency` | No | Order currency. Defaults to the cart currency. |
| `Amount` | No | Order total. Defaults to the cart grand total. |
| `Status` | No | Payment status. Defaults to `CONFIRMED`. |
| `PaidAt` | No | Capture timestamp (ISO-8601). Defaults to now. |

## Response schema

| Field | Description |
| --- | --- |
| `OrderCreateRS.Order.OrderID` | Arcube order id. In the no-PSP flow this equals the aggregation `TransactionRef`. |
| `OrderCreateRS.Order.Status` | Order status (e.g. `confirmed`). |
| `OrderCreateRS.Order.Owner` | `"Arcube"`. |
| `OrderCreateRS.Order.TransactionRef` | Aggregation transaction id (provider booking reference). Use it for OrderCancel and to fetch the transaction. |
| `OrderCreateRS.Order.PNR` | The record locator — the PNR you sent, or the one the order generated (no-PNR tenants). Equals the order's session id. |
| `OrderCreateRS.Order.Items[]` | Every booked item: `OrderItemID`, `OfferItemRef`, `ServiceDefinitionRef`, `ServiceTypeCode`, `Quantity`, `Status`, `PriceDetail.TotalAmount`, plus the delivered artifact (see below). |
| `OrderCreateRS.Order.PriceSummary` | `{ Currency, GrandTotal }` for the whole order. |
| `OrderCreateRS.Metadata` | `CorrelationID`, `PricedSessionID`, `TransactionRef`, `PNR`, `OrderKey`. |

### What the customer actually bought

Beyond the price and the status, each item carries the vendor's own confirmation — the thing the
passenger needs in order to use what they paid for. The block is named after the category and only
appears once the line is `CONFIRMED`:

| `ServiceTypeCode` | Block | Contains |
| --- | --- | --- |
| `ESIMS` | `Passengers[].Sims[]` | ICCID, activation code, QR, `InstallationGuideURL`. |
| `LOUNGE_ACCESS` | `Passengers[].Passes[]` | Pass reference and validity. |
| `FAST_TRACK` | `Passengers[].Vouchers[]` | E-pass id and per-passenger vouchers. |
| `CARBON_OFFSET` | `CarbonOffset` | Certificate reference, project, tonnes offset. |
| `AIRPORT_TRANSFER` | `Transfer` | `Booking` (reservation id, confirmation number, supplier contact), `Legs[]` (flight, vehicle, driver, meet-and-greet instructions), `CancellationPolicy`. |
| `CAR_RENTAL` | `CarRental` | `Booking`, `Vehicle`, `Supplier`, `Driver`, `Itinerary`, `Mileage`, `Inclusions`, `Protections`, `Notices`, `Extras` payable at the desk, `CancellationPolicy`. |
| `BAGGAGE_PROTECTION` | `BaggageProtection` | `Product`, `Coverage.Benefits[]`, `Terms` (payout trigger and report deadline, in hours), `Claims` (tracking URL), `Flight`, and `Policies[]` — one agreement per traveller. |
| `PARKING` | `Parking` | `Booking`, `Reservation`, `Lot` (address, phone, timezone, directions, shuttle info, special conditions), `AmountDueAtLocation`, `CancellationPolicy`. |

`Fulfillment` (`RequestedQuantity` / `DeliveredQuantity` / `FailedQuantity`) appears on any item the
vendor delivers per unit, so a partially-fulfilled line is visible rather than implied.

<Callout type="warn" title="Money still payable at delivery">
  Two categories can leave the passenger owing money we did not collect: `Parking.AmountDueAtLocation`
  and `CarRental.Extras[]` (mandatory desk charges such as airport surcharges). Surface both, or your
  total understates the trip.
</Callout>

<Callout type="info" title="A PENDING line is not a failure">
  Some suppliers confirm asynchronously — an on-request car-rental rate, or baggage protection.
  OrderCreate waits for the vendor to settle before responding, but returns honestly as `PENDING` if
  it does not settle in time. Poll
  [OrderView](/docs/api-offer-order-integration/order-management) for the final state; the same
  blocks appear there once the line confirms.
</Callout>

## Common failure modes

| Error | Cause | Fix |
| --- | --- | --- |
| `Missing PricedSessionID` | Not sent | Send `Metadata.PricedSessionID` from OfferPrice. |
| `Missing x-idempotency-key` | Header absent | Add `x-idempotency-key: <uuid>`. |
| `Recommendation schedule not found` (404) | A stale/unknown `Metadata.PNR` was sent | Omit `Metadata.PNR` — the order generates its own. |
| `Quote bundle not found or expired` | Correlation id inconsistent across the flow, or cart expired | Reuse one `x-correlation-id`; re-run within the cart TTL. |
| `INVALID_ORIGIN` / `Not allowed by CORS` | White-label origin not configured | Ensure the environment is configured for `WHITE_LABEL`. |

See [Errors](/docs/api-offer-order-integration/errors) for the full catalog.
