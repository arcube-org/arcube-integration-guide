Every sellable category and the **OfferPrice `ProductInput`** it requires. In every case the
`ProductInputs[].ServiceDefinitionRef` must equal the selected offer's `ServiceDefinitionRef`.

| Category | `ServiceTypeCode` | Ref prefix | Discovery |
| --- | --- | --- | --- |
| eSIM | `ESIMS` | `SVC-SIM` | General AirShopping |
| Lounge access | `LOUNGE_ACCESS` | `SVC-LNG` | General AirShopping |
| Carbon offset | `CARBON_OFFSET` | `SVC-CO2` | General AirShopping |
| Fast-track | `FAST_TRACK` | `SVC-FT` | General AirShopping |
| Baggage protection | `BAGGAGE_PROTECTION` | `SVC-BAG` | General AirShopping |
| Airport transfer | `AIRPORT_TRANSFER` | `SVC-TRF` | Product search (+ general first) |
| Car rental | `CAR_RENTAL` | `SVC-CAR` | Product search |

---

## eSIM — `ESIMS`

**OfferPrice `Input`:**

| Field | Required | Description |
| --- | --- | --- |
| `metadata.passengers[]` | Yes | `[{ firstName, lastName, email }]` — recipient(s). |

`description` and `serviceDetails` (Region, Country, Data Amount, Validity) are resolved from the
shopping catalog — you don't send them.

```json
{
  "metadata": { "passengers": [ { "firstName": "John", "lastName": "Doe", "email": "john@example.com" } ] }
}
```

## Carbon offset — `CARBON_OFFSET`

**OfferPrice `Input`:**

Nothing is required from the client — `description` and the Project Name are resolved from the
catalog, and the offset is placed from Arcube's recommendation. The fields below are **optional**
and, when sent, only enrich the receipt.

| Field | Required | Description |
| --- | --- | --- |
| `serviceDetails.Route` | Optional | Itinerary, e.g. `"CUN → MAN"`. |
| `serviceDetails.Passengers` | Optional | Passenger count. |
| `metadata.perPassengerPrice` | Optional | Number. |
| `metadata.perPassengerCO2` | Optional | Number. |
| `metadata.co2Unit` | Optional | e.g. `"KG"`. |
| `metadata.totalPassengersInBooking` | Optional | Integer. |
| `metadata.passengersInQuote` | Optional | Integer. |

```json
{
  "serviceDetails": { "Route": "CUN → MAN", "Passengers": 1 },
  "metadata": { "perPassengerPrice": 864.34, "perPassengerCO2": 616.68, "co2Unit": "KG", "totalPassengersInBooking": 1, "passengersInQuote": 1 }
}
```

| Field | Required | Description |
| --- | --- | --- |

## Airport transfer — `AIRPORT_TRANSFER`

<Callout type="warn" title="Discovery requires a general AirShopping first">
  Run a general AirShopping on the **same** `x-correlation-id` before the transfer product search
  (see [AirShopping](/docs/api-offer-order-integration/air-shopping#airport-transfer-airshopping)).
  It provides the vendor context the transfer search needs.
</Callout>

`description`, `serviceDetails` (From / To / Vehicle) and `vendorReferenceId` are resolved from the
transfer search — you don't send them. You supply only booking context.

**OfferPrice `Input`:**

| Field | Required | Description |
| --- | --- | --- |
| `metadata` | Optional | Booking context, e.g. `{ passengers: 1, flight: { airline, flight_number } }`. Include the flight for airport pickups. |
| `serviceDetails` | Optional | May carry `start_coordinates` / `end_coordinates`. |

```json
{
  "metadata": { "passengers": 1, "flight": { "airline": "AA", "flight_number": "1234" } }
}
```

---

## Car rental — `CAR_RENTAL`

`description`, `serviceDetails` and `vendorReferenceId` are resolved from the car-search catalog —
you don't send them. You supply only the driver contact details.

**OfferPrice `Input`:**

| Field | Required | Description |
| --- | --- | --- |
| `driverDateOfBirth` | Yes | `YYYY-MM-DD`. |
| `driverPhoneCountry` | Yes | e.g. `"+30"`. |
| `driverPhoneNumber` | Yes | Driver contact number. |
| `metadata` | Optional | Object. |

```json
{
  "driverDateOfBirth": "1989-07-06",
  "driverPhoneCountry": "+30",
  "driverPhoneNumber": "6981164559"
}
```

<Callout type="info" title="Descriptive fields are resolved for you">
  Arcube resolves the vendor/product identifiers **and** the descriptive fields (`description`,
  `serviceDetails`) from the shopping catalog captured at AirShopping — so you only send the fields
  listed above (recipient/passenger data and any genuine booking-context). The only per-product
  extras are car rental's driver details.
</Callout>
