`POST /offerprice`

OfferPrice takes the offers you selected from one or more AirShopping responses, builds a **cart**
(basket) on Arcube's side, validates and re-prices them, and returns a `PricedSessionID` that
[OrderCreate](/docs/api-offer-order-integration/order-create) books.

<Callout type="info" title="Headers">
  Send the **same** `x-correlation-id` you used on AirShopping, plus `Authorization` and
  `Content-Type: application/json`.
</Callout>

## Request schema

The body is a single `OfferPriceRQ`.

| Field | Required | Description |
| --- | --- | --- |
| `Document.Name` / `Document.ReferenceVersion` | Yes | Request label + schema version. |
| `Party.Sender.AgentUser.Name` | Yes | Calling system name. |
| `Query.SelectedOffers[]` | Yes | The offers to cart. One entry per offer (see below). |
| `Metadata.SessionID` | Yes | Set to the **CorrelationID** from AirShopping. Its presence selects the basket flow. |
| `Metadata.Tenant` | Optional | Tenant id. |
| `ProductInputs[]` | **No** | Per-product inputs, keyed by `ServiceDefinitionRef`. Omit it entirely unless a product needs something the search could not know — see [Products](/docs/api-offer-order-integration/products). |

### `SelectedOffers[]`

| Field | Required | Description |
| --- | --- | --- |
| `OfferID` | Yes | `OtherOfferID` of the chosen offer. |
| `ShoppingSessionID` | Yes | The `Metadata.ShoppingSessionID` of the AirShopping response the offer came from. |
| `Owner` | Yes | The AirShopping response `OtherOffers.Owner` (`"Arcube"`). |
| `OfferItems[]` | Yes | The chosen item(s). |
| `OfferItems[].OfferItemID` | Yes | From AirShopping. |
| `OfferItems[].ServiceDefinitionRef` | Yes | From AirShopping. |
| `OfferItems[].Quantity` | Yes | Usually `1`. |
| `OfferItems[].Currency` / `OfferItems[].Price` | Yes | Echoed selection price. The authoritative price is taken from the catalog. |

### `ProductInputs[]`

**Optional.** Each entry supplies data for one selected service, matched by
`ServiceDefinitionRef`.

| Field | Description |
| --- | --- |
| `ServiceDefinitionRef` | Must match a selected `OfferItems[].ServiceDefinitionRef`. |
| `Input` | Category-specific object. See [Products](/docs/api-offer-order-integration/products) for what each `ServiceTypeCode` takes. |

<Callout type="info" title="Most carts need no ProductInputs at all">
  Product and vendor identifiers, `description`, `serviceDetails`, prices, quote tokens, search
  dates, the car-rental driver and **the traveller list** are all resolved server-side from the
  shopping session. eSIM, lounge access, carbon offset, baggage protection and car rental cart with
  the field omitted entirely. Send an entry only to supply something the search could not know —
  the fast-track visit slot, the airport-transfer flight, a parking lot's licence-plate field — or
  to override a resolved default.
</Callout>

<Callout type="warn" title="What is still enforced">
  Two things are checked and refused rather than allowed to fail at the vendor:

  - a traveller with no email address, for the products delivered by email (eSIM, lounge,
    fast-track);
  - a missing `flight` on an airport transfer whose offer advertises `flightInfoRequired`.

  Anything you do send is validated against its category schema; a mismatch fails with
  `Basket input validation failed`.
</Callout>

## Example request (single eSIM)

The passengers were named once in the AirShopping request, so there is nothing left to send per
product — `ProductInputs` is omitted entirely:

```json title="POST /offerprice"
{
  "OfferPriceRQ": {
    "Document": { "Name": "OfferPrice", "ReferenceVersion": "1.0" },
    "Party": { "Sender": { "AgentUser": { "Name": "Arcube API" } } },
    "Query": {
      "SelectedOffers": [
        {
          "OfferID": "2d1842ea-c534-4ff4-81e4-44dc34cf4b08",
          "ShoppingSessionID": "df03ef63-335f-4a47-a302-1e13d5b89649",
          "Owner": "Arcube",
          "OfferItems": [
            {
              "OfferItemID": "SIM-2d1842ea-c534-4f",
              "ServiceDefinitionRef": "SVC-SIM-2d1842ea-c534-4f",
              "Quantity": 1,
              "Currency": "USD",
              "Price": 1
            }
          ]
        }
      ]
    },
    "Metadata": { "SessionID": "159b2361-3bc8-420d-a0f8-ba55c33187e2", "Tenant": "6941cc3502a186f72ba55226" }
  }
}
```

## Response schema

| Field | Description |
| --- | --- |
| `OfferPriceRS.PricedSessionID` | The cart id. Pass it to OrderCreate. |
| `OfferPriceRS.PricedOffers[]` | One priced offer per selected item. |
| `OfferPriceRS.PricedOffers[].OfferID` | Priced offer id. |
| `OfferPriceRS.PricedOffers[].OfferItems[].OfferItemID` / `.ServiceDefinitionRef` | Item references for OrderCreate. |
| `OfferPriceRS.PricedOffers[].PriceSummary.Currency` / `.GrandTotal` | Per-offer total. |
| `Metadata.CorrelationID` | Echoed correlation id. |

## Multi-product carts

Send several `SelectedOffers` in one call (with a `ProductInputs` entry for any that needs one). They land in a single
cart; the response returns one `PricedOffers[]` entry per item, and OrderCreate books them all.

<Callout type="warn" title="One currency per cart">
  All carted items must price in the same currency, or OfferPrice returns
  `Mixed currencies are not supported`.
</Callout>

See the [multi-product example](/docs/api-offer-order-integration/examples#multi-product-order).

## Multi-session carts

`SelectedOffers` may reference **different** `ShoppingSessionID`s — offers gathered from several
AirShopping calls. OfferPrice loads each shopping session, merges their catalogs, and prices them
together.

<Callout type="warn" title="All contributing AirShopping calls must share one correlation id">
  OfferPrice will price a multi-session cart even if the sources used different correlation ids,
  but **OrderCreate will then fail** with `Quote bundle not found or expired`. Ensure every
  AirShopping call that contributes to the cart used the **same** `x-correlation-id`.
</Callout>

See the [multi-session example](/docs/api-offer-order-integration/examples#multi-session-order).
