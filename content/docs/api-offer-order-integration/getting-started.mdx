This page gets you from zero to a booked ancillary as quickly as possible.

## Prerequisites

- **Credentials** — a `clientId` and `clientSecret` issued by Arcube.
- **Base URL** — your assigned NDC-like API environment, referred to below as `${arcube-url}`
  (e.g. `https://qa-ndc-api.arcube.com`). Arcube provides this per environment.
- An HTTP client capable of sending JSON with custom headers.

## Authentication

All NDC-like API calls require a **Bearer token**. Obtain one from the authentication endpoint
using your credentials, then send it on every request.

<Callout type="info" title="HTTP Method: POST">
  **URL:** `${arcube-url}/auth/api/login`
</Callout>

```json title="Request body"
{
  "clientId": "<your-client-id>",
  "clientSecret": "<your-client-secret>"
}
```

```json title="Response"
{
  "accessToken": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "expiresIn": "24h",
  "tokenType": "Bearer"
}
```

Send the token on every subsequent call:

```http
Authorization: Bearer <accessToken>
```

<Callout title="Tenant resolution">
  Your Arcube **tenant** is resolved from the Bearer token — you do not need to send it, though
  several request bodies include a `Tenant`/`Metadata.Tenant` field for explicit routing. See
  [Authentication](/docs/reference/authentication) for token lifecycle details.
</Callout>

## Required headers

| Header | Applies to | Required | Notes |
| --- | --- | --- | --- |
| `Authorization: Bearer <token>` | All calls | Yes | From the login step. |
| `Content-Type: application/json` | All calls | Yes | Request bodies are JSON. |
| `x-correlation-id: <uuid>` | AirShopping, OfferPrice, OrderCreate | Recommended | The thread that ties the flow together. If omitted on AirShopping, Arcube generates one and returns it — **capture and reuse it**. See [Key Concepts](/docs/api-offer-order-integration/key-concepts#the-correlation-id). |
| `x-idempotency-key: <uuid>` | **OrderCreate** | Yes | Guarantees a booking is created at most once. Use a fresh UUID per order attempt. |

<Callout type="warn" title="Correlation id is mandatory across the flow">
  The **same** `x-correlation-id` must be sent on AirShopping, OfferPrice, and OrderCreate.
  If they differ, OrderCreate will fail with `Quote bundle not found or expired`.
</Callout>

## Endpoints at a glance

| Method | Path | Description |
| --- | --- | --- |
| `POST` | `/auth/api/login` | Obtain a Bearer token |
| `POST` | `/airshopping` | Discover ancillary offers |
| `POST` | `/offerprice` | Cart + price selected offers |
| `POST` | `/ordercreate` | Book the cart |
| `POST` | `/orderview` | Retrieve a created order |
| `POST` | `/orderlist` | List orders for a customer |

## Minimal happy path

The shortest route to a booking (an eSIM here). Each step's output feeds the next.

**1. Discover** — `POST /airshopping` with a flight itinerary. Capture
`Metadata.CorrelationID`, `Metadata.ShoppingSessionID`, and pick an offer whose
`ServiceDefinitionRef` starts with `SVC-SIM`.

**2. Cart + price** — `POST /offerprice` with the selected offer and its
`ProductInputs`. Capture `OfferPriceRS.PricedSessionID` and `PricedOffers[0]`.

**3. Book** — `POST /ordercreate` with the `PricedSessionID`, an `externalPSP`
payment block, and a customer. Include a real airline **PNR** unless your tenant is
enabled for no-PNR ordering. Receive `OrderID` and `TransactionRef`.
