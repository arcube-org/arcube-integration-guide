## Prerequisites

Before integrating, make sure you have:

- **Tenant ID** - your Arcube tenant identifier.
- **Cancellation widget URL** - provided by Arcube, referred to below as `CANCELLATION_WIDGET_URL`.
- **Allow-listed origins** - every origin your pages request widget tokens from, registered with Arcube.

---

## Getting a Widget Token

The widget needs a short-lived widget token for the passenger's PNR. It is the same token the [Arcube widget](/docs/widget-integration/implementation#authentication-and-token-flow) uses, requested from the same edge endpoint:

| Environment | Endpoint |
|---|---|
| Development | `https://dev-edge.arcube.io/token` |
| QA | `https://qa-edge.arcube.io/token` |
| Production | `https://edge.arcube.io/token` |

Send a `POST` request with your tenant ID in the `X-Tenant-ID` header and the PNR in the body. The request must come from an origin allow-listed for your tenant.

```bash
curl -X POST https://edge.arcube.io/token \
  -H "X-Tenant-ID: YOUR_TENANT_ID" \
  -H "Origin: https://www.airline.com" \
  -H "Content-Type: application/json" \
  -d '{"pnr":"ABC123"}'
```

```json
{
  "accessToken": "<widget-token>",
  "expiresIn": "1h"
}
```

The token is valid for 60 minutes and opens only the orders for that PNR with your airline. The PNR you pass to the widget must be the same PNR the token was issued for.

<Callout type="warn" title="Token expiry">
  The widget does not renew its token. Request a new token each time the page loads the widget, and reload the iframe with a fresh token if the passenger keeps the page open for more than 60 minutes. With an expired token the widget cannot load orders or cancel, and shows an error.
</Callout>

## Embedding the Widget

Load the widget in an iframe with the PNR and the token as query parameters, and resize the iframe when the widget reports its height:

```html
<iframe
  id="arcube-cancellation-widget"
  src="https://CANCELLATION_WIDGET_URL/?pnr=ABC123&token=WIDGET_TOKEN"
  title="Manage add-ons"
  scrolling="no"
  style="display: block; width: 100%; height: 480px; border: 0;"
></iframe>

<script>
  const WIDGET_ORIGIN = "https://CANCELLATION_WIDGET_URL";
  const frame = document.getElementById("arcube-cancellation-widget");

  window.addEventListener("message", (event) => {
    if (event.origin !== WIDGET_ORIGIN) return;
    const message = event.data || {};

    // Grow the iframe to the widget's content, so your page owns the only scrollbar.
    if (message.type === "ARCUBE_WIDGET_HEIGHT") {
      frame.style.height = `${message.height}px`;
    }

    // An add-on was cancelled: refresh anything on your page that shows it.
    if (message.type === "ARCUBE_WIDGET_CANCELLED") {
      console.log("Cancelled", message.itemId, message.reference);
    }
  });
</script>
```

### Query Parameters

| Parameter | Required | Description |
|---|---|---|
| `pnr` | Yes | The booking PNR. Orders are matched exactly, so pass it as it was booked (usually upper case). |
| `token` | Yes | The widget token issued for that PNR. |
| `accent` | No | Brand colour for the primary button and highlights, for example `%23B3122E` (`#B3122E`). |
| `font` | No | Font family, for example `Manrope, Arial, sans-serif`. The widget runs in its own frame, so the font must be installed on the passenger's device or loaded by a stylesheet you give the widget. |
| `radius` | No | Corner radius in pixels, for example `12`. |
| `theme` | No | Name of a stylesheet Arcube hosts for you. See [Styling and Branding](#styling-and-branding). |
| `cssUrl` | No | URL of your own stylesheet. See [Styling and Branding](#styling-and-branding). |

Without `pnr` and `token` the widget shows "Missing required parameters: pnr and token." That page sends no messages to your page, so the iframe keeps its initial height, and it ignores the styling parameters.

## Events

The widget and your page talk through `postMessage`. Always check `event.origin` against the widget URL before acting on a message.

| Message | Direction | When |
|---|---|---|
| `ARCUBE_WIDGET_READY` | Widget → page | The widget has loaded and can accept `ARCUBE_WIDGET_STYLE`. |
| `ARCUBE_WIDGET_HEIGHT` | Widget → page | The content height changed. `height` is in pixels; set the iframe to it. |
| `ARCUBE_WIDGET_CANCELLED` | Widget → page | An add-on was cancelled, or its cancellation was received for review. Carries `transactionId`, `itemId`, `status` (`completed` when the supplier confirmed the cancellation, otherwise a review status such as `NEEDS_REVIEW`) and `reference` (the cancellation reference, `cncl_…`). |
| `ARCUBE_WIDGET_STYLE` | Page → widget | Styling from your page. See [Styling and Branding](#styling-and-branding). |

## What the Passenger Sees

The widget lists the add-ons for the PNR, one section per order, newest first. Each section shows the order reference, the purchase date and a **Receipt** link that downloads the order's PDF receipt.

Each add-on row shows:

- **When** - the service date and time, in the local time of the service location (for example the pickup time at the airport). Add-ons without a service time, such as eSIMs, leave this blank.
- **What** - the add-on's name and details, for example "Transfer to Lexington Hotel" and "Private SUV · 2 travellers".
- **Cancellation terms or status** - one line, described below.
- **Price** - what the passenger paid. Cancelled add-ons are greyed out with the price struck through.

### Cancellation Terms

For an add-on that can be cancelled online, the line shows Arcube's current terms:

| Line | Meaning | Cancel shown |
|---|---|---|
| Checking cancellation options… | The terms are being checked. | No |
| Free cancellation until 13 Dec, 04:30 | Cancelling now refunds the full price. | Yes |
| 50% refund if cancelled before 12 Dec, 04:30 | Cancelling now refunds part of the price. | Yes |
| Non-refundable, with a **Cancel** link | It can be cancelled, but nothing is refunded. | Yes. Confirming needs the passenger to tick "I understand I won't get a refund." |
| Free cancellation ended 12 Oct, 11:00 | The cancellation window has passed. | No |
| Non-refundable | The supplier does not allow cancelling. | No |
| Contact support to cancel | The cancellation has to be handled by support. | No |
| Can't be cancelled online | The add-on is not cancellable online (see [Cancellation Eligibility](#cancellation-eligibility)), or Arcube's rules don't allow cancelling it online. | No |
| Cancellation options unavailable right now | The terms could not be checked. Reloading the widget checks again. | No |

Deadlines are shown in the local time of the service location. When the deadline isn't known, the lines read "Free cancellation", "USD 24.00 back if cancelled now" and "The cancellation window has passed". When the percentage isn't known, a partial refund reads "Partial refund if cancelled before 12 Dec, 04:30".

### Statuses

Add-ons that are not live show their status instead of terms:

| Status | Line shown |
|---|---|
| `CONFIRMED` | The cancellation terms above. |
| `PENDING` | Waiting for the provider to confirm |
| `CANCELLATION_INITIATED` | Cancellation in progress |
| `CANCELLED` | Cancelled |
| `REFUND_IN_PROGRESS` | Cancelled · refund on its way. When your airline took the payment: Cancelled · refund due from the airline (see [Who Refunds the Passenger](#who-refunds-the-passenger)). An add-on the supplier never confirmed reads "Couldn't be booked · refund on its way". |
| `REFUNDED` | Cancelled · refunded |
| `REFUND_MANUAL_REVIEW` | Cancelled · refund under review |
| `FAILED` | Couldn't be booked · refund on its way |
| `COMPLETED`, `DELIVERED` | Can't be cancelled online |
| Any other status | The status in words, for example "Uncertain". |

Right after a cancellation, until the order reloads, the line reads "Cancelled · USD 48.00 refund on its way", "Cancelled · the airline will refund USD 48.00", "Cancelled" when nothing was refunded, or "Cancelled · refund under review".

## Cancellation Eligibility

The **Cancel** link appears only when all of these hold:

1. The add-on's status is `CONFIRMED`.
2. It is an airport transfer, car rental or parking booking. eSIMs, lounge access, fast track, carbon offsets and baggage protection can't be cancelled from the widget.
3. Arcube confirms the add-on can be cancelled at that moment. The terms are checked when the page loads and again immediately before cancelling.

If the terms change between the two checks, for example because the free-cancellation deadline passed while the page was open, nothing is cancelled. The panel shows either "This add-on can't be cancelled online any more" with Arcube's explanation and a **Close** button, or "The refund for this add-on has changed to USD 40.00. Check it and confirm again."

## Cancelling an Add-on

1. The passenger selects **Cancel** on an add-on. A panel opens under it with the refund ("Full refund", "Partial refund" or "No refund") and the amount.
2. The passenger confirms with **Cancel and refund USD 48.00**, or **Cancel without refund** after ticking the acknowledgement. **Keep it** closes the panel. While the cancellation is sent, the button reads "Cancelling…".
3. The widget shows the outcome under the add-on:
   - "Transfer cancelled. USD 48.00 is on its way back to the card you paid with and should appear within 5–10 business days. Reference cncl_…" when Arcube took the payment.
   - "Transfer cancelled. The airline will refund USD 48.00 to the card you paid with. Reference cncl_…" when your airline took the payment.
   - "Transfer cancelled. Your booking has been released. No refund was due. Reference cncl_…" after a cancellation without refund.
   - "Transfer cancelled. We're checking the refund and will process it shortly. Reference cncl_…" when the supplier confirmed the cancellation but the refund needs a check by Arcube.
   - "Cancellation received. We're checking the refund with the provider and will process it shortly. Reference cncl_…" when the supplier has not confirmed the cancellation yet.
4. The widget sends `ARCUBE_WIDGET_CANCELLED` to your page.

A cancelled add-on can't be restored; the passenger can book it again.

### Who Refunds the Passenger

Refunds go back to the card the passenger paid with. Who sends them depends on who took the payment:

| Payment taken by | Refund sent by | What the widget says |
|---|---|---|
| Arcube's checkout | Arcube, automatically | The refund should appear within 5–10 business days. |
| Your airline, through its own payment provider (orders created with `externalPSP`) | Your airline | The airline will refund the passenger. No timing is promised, since the timing is your airline's. |

The confirmation panel follows the same rule. For a full refund it reads "Back to the card you paid with within 5–10 business days." when Arcube took the payment, and "The airline will refund this to the card you paid with." when your airline did, followed by the free-cancellation deadline when it is known. For a partial refund it starts "The provider keeps the rest of the price." For no refund it shows Arcube's explanation of the terms.

<Callout type="warn" title="Your airline must refund and confirm">
  When your airline took the payment, Arcube cancels the add-on but cannot refund the passenger.
  Your airline refunds them and confirms each refund to Arcube, from the dashboard or the API. See
  [Airline Refunds](/docs/cancellation-widget/refunds).
</Callout>

## Styling and Branding

Every element of the widget can be restyled to match your brand. The widget's default styles have the lowest priority (they sit in a CSS cascade layer), so your CSS overrides them with ordinary selectors. You do not need `!important`, and should not use it.

From lowest to highest priority:

1. The widget's defaults.
2. Tokens from the `accent`, `font` and `radius` query parameters.
3. Tokens sent by `ARCUBE_WIDGET_STYLE`.
4. Stylesheets: a `theme` hosted by Arcube, then your `cssUrl`, then a stylesheet or CSS text sent by `ARCUBE_WIDGET_STYLE`.

### Ways to Supply Styling

**Query parameters** - quick colour, font and corner changes:

```text
https://CANCELLATION_WIDGET_URL/?pnr=ABC123&token=WIDGET_TOKEN&accent=%23B3122E&font=Manrope&radius=12
```

**A theme hosted by Arcube** - send Arcube your stylesheet and pass the theme name you are given:

```text
https://CANCELLATION_WIDGET_URL/?pnr=ABC123&token=WIDGET_TOKEN&theme=your-airline
```

**Your own stylesheet** - pass its URL in `cssUrl`. It is loaded only over HTTPS, and only from the origin of the page embedding the widget or from an origin Arcube has allow-listed for you (for example your CDN). Any other URL is ignored. A stylesheet URL sent with `ARCUBE_WIDGET_STYLE` (below) only has to be HTTPS, since only the page embedding the widget can send that message.

```text
https://CANCELLATION_WIDGET_URL/?pnr=ABC123&token=WIDGET_TOKEN&cssUrl=https%3A%2F%2Fwww.airline.com%2Fwidget.css
```

The widget learns the embedding page's origin from the browser. If your page sends `Referrer-Policy: no-referrer`, some browsers withhold it, so host the stylesheet on an origin Arcube has allow-listed, or send it with `ARCUBE_WIDGET_STYLE`.

**From your page** - after the widget sends `ARCUBE_WIDGET_READY`, post `ARCUBE_WIDGET_STYLE`. Every field is optional; sending a field again replaces what you sent before, and an empty value clears it. CSS text longer than 200,000 characters is cut off.

```javascript
window.addEventListener("message", (event) => {
  if (event.origin !== WIDGET_ORIGIN) return;
  if (event.data?.type === "ARCUBE_WIDGET_READY") {
    frame.contentWindow.postMessage(
      {
        type: "ARCUBE_WIDGET_STYLE",
        tokens: { accent: "#B3122E", "--arc-panel-bg": "#FFF8F6" },
        cssUrl: "https://cdn.airline.com/arcube/cancellation-widget.css",
        css: ".arc-title { font-weight: 800; }",
      },
      WIDGET_ORIGIN,
    );
  }
});
```

### Design Tokens

Set any of these on `:root` in your stylesheet, or by name in the `tokens` of `ARCUBE_WIDGET_STYLE`. The `tokens` object also accepts `accent`, `accentText`, `font`, `radius`, `background` and `text` as short names. Values must be valid CSS: `radius` takes any CSS length, such as `12px` or `0.75rem`. Unknown token names, and values that try to do more than set a value (for example ones containing `;`, `{`, `}` or `url(`), are ignored.

| Token | Default | Used for |

### State Attributes

Each `.arc-item` describes its state in data attributes, so you can style each case:

| Attribute | Values |
|---|---|
| `data-state` | `active`, `pending`, `cancelling`, `cancelled`, `failed` |
| `data-policy` | `checking`, `free`, `partial`, `no-refund`, `expired`, `nonrefundable`, `review`, `unavailable`, `none` (matching the [terms table](#cancellation-terms)) |
| `data-category` | The add-on's category, for example `AIRPORT_TRANSFER`, `CAR_RENTAL`, `PARKING`, `ESIMS`, `LOUNGE_ACCESS` |
| `data-open` | `true` while the add-on's refund panel or confirmation is showing |

The refund panel carries `data-refund` (`full`, `partial` or `none`). Each `.arc-order` carries `data-order-id`. The **Receipt** link carries `data-state="busy"` while it downloads ("Downloading…") and `data-state="error"` when the receipt can't be downloaded ("Receipt unavailable, try again"). The acknowledgement `.arc-ack` carries `aria-checked`, for styling the ticked box.

```css
:root {
  --arc-font: Manrope, "Helvetica Neue", Arial, sans-serif;
  --arc-accent: #b3122e;
  --arc-radius: 16px;
}

.arc-order__title {
  text-transform: uppercase;
  letter-spacing: 0.1em;
}

.arc-item[data-policy="free"] .arc-item__policy::before {
  content: "✓ ";
}

.arc-item[data-state="cancelled"] {
  opacity: 0.7;
}
```

Class names, data attributes and tokens are part of the widget's public interface, so your stylesheet can rely on them.

## Error Handling

- **No add-ons on the PNR:** "There are no add-ons on this booking yet." This is also what a token issued for a different PNR shows.
- **Expired or invalid token:** "We couldn't load your add-ons. This page has expired. Reload the page to see them." Request a new token and reload the iframe.
- **Orders can't be loaded** for another reason: "We couldn't load your add-ons. Check your connection and try again." when the request didn't reach Arcube, or "…Please try again in a moment." otherwise, with a **Try again** button.
- **Missing parameters:** "Missing required parameters: pnr and token."
- **The terms can't be checked:** the add-on shows "Cancellation options unavailable right now" and offers no Cancel.
- **The terms can't be re-checked when the passenger confirms** (for example the token expired while the page was open): "We couldn't confirm the cancellation terms right now. Please try again." in red inside the refund panel. Nothing is cancelled.
- **A cancellation fails:** "We couldn't cancel this add-on right now." followed by Arcube's reason, in red inside the refund panel. The passenger can try again; a retry does not cancel twice.
- **The receipt can't be downloaded:** the **Receipt** link reads "Receipt unavailable, try again".
